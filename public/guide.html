部署与使用教程

从准备授权，
到完成第一笔收款。

先部署支付站，再配置通道。Docker 和微信监听按所选插件需要设置，不必逐项安装。

开始前，准备这四项

  • 正式支付域名已接入你的 Cloudflare 账户
  • 永久 License与支付域名一致，免费插件也需要
  • API Token + Account ID用于向导校验与发布
  • 收款平台资料账号、密钥或真实收款二维码

第一次使用：按 01 → 02 → 03 完成主流程。部署平台二选一：Cloudflare Workers 看 02；主要面向中国大陆、域名已备案时选 EdgeOne Makers，看 02B。需要容器监听时，再阅读 04 或 05。

01

获取永久 License

  1. 打开 license.imsuk.cn。
  2. 填写准备绑定给支付 Worker 的正式域名，例如 pay.example.com。这里不要填写 license.imsuk.cn。
  3. 免费插件默认包含，无需付款。按需选择付费插件；未选付费插件时可直接生成免费授权。
  4. 生成后立即复制并妥善保存以 EPL1. 开头的 License。同域名增购继续使用同一串 License；换绑域名会生成新 License，原授权随即失效。
License 与域名严格绑定。部署向导中的“公开访问地址”必须使用同一域名。
02

部署到 Cloudflare Workers

先完成凭据校验，再填写项目。新建会创建资源；升级会识别并保留原项目配置。

  1. 回到 deploy.imsuk.cn，填写 Cloudflare API Token 和 Account ID。
  2. 填写项目名、管理员用户名、管理员密码和公开访问地址，例如 https://pay.example.com。管理员密码为新建部署必填项。
  3. Watcher 通信密钥可以自行填写；留空时向导会生成高强度随机值，完成后把它填入容器的 TRANSPORT_KEY。
  4. 将刚才保存的 License 粘贴到“EdgePay 永久 License”。向导会在线验签并核对域名。
  5. 客户项目只创建一个 D1，页面随 Worker 程序发布，不额外创建 KV 或静态资源命名空间。同名 D1 仅在没有订单、插件配置和运行配置时复用。
  6. 确认后开始部署，保存完成页显示的所有密钥，尤其是 ADMIN_TOKEN 和 WATCHER_TRANSPORT_SECRET。
  7. 向导会把 License 域名直接绑定到支付 Worker，不启用 workers.dev；该域名必须位于当前 Cloudflare 账号。

后台定时轮询（Cron）与可选的 tick 地址

部署向导默认勾选“启用每分钟 Cron 自动轮询收款”：Worker 每分钟自动跑一轮订单过期、商户通知重投、监听端掉线巡检和收款轮询，不需要额外配置。

  • 可选：想比每分钟更快确认到账，或部署时没有启用 Cron，可以用外部定时器每 7～15 秒访问一次 https://你的支付域名/internal/tick?token=你的POLL_TRIGGER_TOKEN。它做的事和 Cron 完全一样，返回值里的 receipt_poll 是这一轮收款轮询的明细。
  • 完整地址在支付站后台“使用文档 → Worker 主动查询”里可以直接复制。已经启用 Cron、到账速度也满意时，不需要配它。

API Token 与 Account ID 去哪里找？

在 Cloudflare API Token 页面创建自定义令牌。在目标账户的概览或 Workers & Pages 页面复制 Account ID，它是 32 位十六进制字符，不是域名的 Zone ID。Token 的账户资源范围必须包含这个账户。

权限示例见下图：账户级 D1:Edit 与 Workers Scripts:Edit，账户资源选择实际部署账号。需要上传微信退款 mTLS 证书时，再加账户级 SSL and Certificates:Edit；如果证书权限探测提示异常但你已确认权限齐全，可以继续部署，最终以 Cloudflare 上传步骤返回为准。

02B

部署到 EdgeOne Makers（腾讯云）

主要面向中国大陆用户、域名已备案时选这个平台。程序、后台和插件与 Cloudflare 版完全一样，差别只在平台：数据库用你自备的 PostgreSQL，定时任务要自己配一个定时器，域名在 Makers 控制台绑定。

先准备这几项

  • 开通 EdgeOne Makers —— 中国站在腾讯云控制台，国际站在 Tencent Cloud 控制台。两个站点的账号和 Token 互不通用。
  • Makers API Token —— 在 Makers 控制台的 API Token 页面创建。它能管理整个账号的 Makers 项目，部署完可以删掉。
  • PostgreSQL 数据库 —— 14 及以上版本，必须允许公网连接，账号要有建表权限。支付站第一次被访问时会自动建表，升级时自动补齐表结构。强烈建议开启 SSL，并在连接串末尾加 ?sslmode=require&uselibpqcompat=true；没开 SSL 时数据库密码和订单数据会明文经过公网。
  • 域名 —— 与 License 绑定的域名。加速区域选“全球（含中国大陆）”时，域名必须已完成 ICP 备案；选“中国大陆以外”免备案，但大陆访问速度和 Cloudflare 差不多。

用部署站完成部署

  1. 打开 deploy.imsuk.cn，选择 EdgeOne Makers，选站点并粘贴 API Token。
  2. 填写项目名、加速区域、PostgreSQL 连接串、管理员用户名和密码、公开访问地址和 License。向导会在线验签并核对域名。
  3. 确认后开始部署。向导会创建 Makers 项目、写入环境变量、上传程序并等待 Makers 构建（通常 1～2 分钟），最后访问一次 /health 确认支付站连上了数据库。
  4. 保存完成页显示的所有密钥，尤其是 ADMIN_TOKEN、POLL_TRIGGER_TOKEN 和 WATCHER_TRANSPORT_SECRET。

绑定自定义域名

  1. 在 Makers 控制台打开这个项目，进入域名管理，添加 License 绑定的域名。
  2. 按控制台提示到域名解析服务商添加 CNAME 记录，等状态变成已生效。
  3. 绑定生效前，支付回调、收银台链接和 License 在线校验都用不了；可以先用完成页上的 Makers 默认域名打开后台做配置。中国大陆访问默认域名需要控制台生成的预览链接（3 小时有效）。

配置定时轮询（必须）

Makers 没有分钟级定时任务。订单过期、商户通知重投、监听端掉线巡检和收款轮询，都靠一个外部定时器按固定间隔访问下面这个地址来驱动；每访问一次，支付站就完整跑一轮，所以只需要配这一个地址：

https://你的支付域名/internal/tick?token=你的POLL_TRIGGER_TOKEN
  • 建议每 7～15 秒访问一次，推荐 10 秒。间隔越短到账确认越快，但函数调用次数也越多（10 秒一次约每月 26 万次）；超过 15 秒会明显拖慢到账确认和通知重投。
  • 完成页和支付站后台“使用文档 → 定时轮询”都会给出已填好 Token 的完整地址，直接复制即可。
  • 没有待处理订单时，这个地址只查一次数据库就返回，空跑成本很低。返回值里的 receipt_poll 是这一轮收款轮询的明细，排查时直接看它。
  • 不配的话，只有收银台打开期间才会查询到账；订单不会自动过期，商户通知失败也不会重投。
  • 地址里带着轮询 Token，不要公开。泄露后到后台“密钥管理”轮换轮询 Token，再更新定时器。

有一台长期开机、装了 Docker 的 Linux 服务器或 NAS 时，用下面这条命令常驻运行即可（把地址换成完成页上那一条）：

docker run -d --name edgepay-tick --restart unless-stopped alpine sh -c 'while true; do wget -q -T 30 -O /dev/null "你的定时轮询地址"; sleep 10; done'

也可以用青龙面板、Uptime Kuma 等支持秒级间隔的监控或定时工具，按 GET 请求访问同一地址。系统自带的 crontab 最小间隔是 1 分钟，不适合单独使用。

Makers 的环境变量值会被过滤“危险字符串”，向导生成的密钥一律是十六进制；如果部署时提示某个值被拒收，多半是管理员密码或自定义的 Watcher 通信密钥，换一个即可。
03

配置通道，验证第一笔收款

打开支付站 /admin，使用部署时设置的管理员用户名和密码登录。先保存插件配置，再创建支付通道；需要 Docker 的插件请先完成下一节。

  1. 登录支付站的管理后台，打开“插件配置”，进入准备使用的平台。先填写并保存平台账号密码；直连插件也可填写 Token 或 Cookie。商户号、门店号、终端号和码牌 ID 不知道时先留空。
  2. 用准备接入的目标码牌或终端真实收一笔容易辨认的小额款，等第三方平台显示交易成功。同一时间尽量只测试一台终端。
  3. 在 5 分钟内回到插件编辑区，点击“查询最近流水”。纯 Docker 插件会把任务交给在线 Watcher，其它插件由 Worker 直接查询。
  4. 按支付时间、金额、支付方式和商户名称找到目标流水，点击“填入编号”。系统只填平台实际返回、且当前插件需要的商户/门店/终端/码牌字段。
  5. 核对编号，上传目标码牌的真实二维码，补齐图鉴等插件专用字段，保存后启用插件。
  6. 进入“通道管理”新增通道。一个通道只选一种支付方式；同一插件同时收微信和支付宝时分别建两条通道。
  7. 点击通道右侧“测试”，按收银台显示金额真实付款，确认订单状态变为“已支付”。若已接入业务系统，再核对回调是否成功、业务订单是否同步更新。
最近流水只读取近 5 分钟成功交易，最多显示 20 条；不会创建或确认订单，也不展示付款人、备注、Cookie 或 Token。平台没有返回的编号保持空白，不要用订单流水号代替终端号。
04

按需启动 Docker 监听器

付呗、收钱吧等能由 Worker 直接查询的平台可以先跳过本节。富友、拉卡拉普通版、星驿付普通版、天阙会生活、易宝老板管账、易生收款啦和盛付通必须保持 Docker 在线。公开镜像同时提供 AMD64 与 ARM64 版本：

docker pull ghcr.io/suk-ldev/edgepay-watcher:latest

方式一：一条指令启动（已安装 Docker 的服务器 / NAS）

先准备一个用于持久化的宿主机目录，再将下方四处中文替换为真实值。本方式不需要 .env 或 Compose 文件。下面是直连版，只需执行与你所选版本对应的一条启动命令：

docker run -d --name payment-watcher --restart unless-stopped -e TZ=Asia/Shanghai -e WORKER_URL="你的支付站地址" -e TRANSPORT_KEY="你的Watcher传输密钥" -e EDGEPAY_LICENSE="你的License" -e POLL_SECONDS=15 -e MAX_CONCURRENCY=2 -e WATCHER_STORAGE_DIR=/app/var/storage -v "你的存储目录":/app/var/storage --security-opt no-new-privileges:true ghcr.io/suk-ldev/edgepay-watcher:latest

示例统一使用官方镜像源 ghcr.io。如需镜像加速服务，请自行确认来源；启动、更新时使用同一镜像源和版本标签。

两个版本，按需要选一个

  • :latest —— 直连版，不含浏览器，适合接口直连插件。付呗、收钱吧、支付宝账单、USDT TRC20 等走接口直连的插件都在这个版本里。按实际插件的运行要求选择。
  • :latest-browser —— 浏览器版，内置 Chromium headless shell。富友、拉卡拉普通版、星驿付普通版、天阙会生活、易宝老板管账、易生收款啦、盛付通这些必须走网页登录的平台需要它。浏览器版包含全部直连插件，既有直连又有浏览器平台时只需要这一个容器，不用开两个。

选错也不会静默出问题：直连版启动时会把需要浏览器的插件筛掉，并在日志里写明缺哪些、该换哪个镜像。

四处要改的地方：

  • 你的支付站地址 —— 支付 Worker 的 HTTPS 正式地址，例如 https://pay.example.com。必须和 Payment 的 PUBLIC_BASE_URL、License 绑定域名完全一致，结尾不要带斜杠。
  • 你的Watcher传输密钥 —— 部署完成页上的 WATCHER_TRANSPORT_SECRET，请完整复制，不要添加空格。遗失时可在支付后台“密钥管理”轮换，并同步更新所有监听容器。
  • 你的License —— 从 license.imsuk.cn 生成的 EPL1 开头的 License，和支付 Worker 用的是同一个。只用免费插件时可以把这一整段 -e EDGEPAY_LICENSE=... 删掉。
  • 你的存储目录 —— 宿主机上放登录态和缓存的目录，例如 /opt/edgepay-watcher/storage，请先创建并确认容器具有读写权限。建议使用绝对路径；NAS 可在文件管理器中创建。容器内路径 /app/var/storage 保持不动。
用浏览器版时，把镜像名换成 …edgepay-watcher:latest-browser，并在镜像名之前再加一段 --shm-size 256m：浏览器需要更多共享内存，默认配额可能导致进程异常退出。直连版不需要加。

要用浏览器版的话，换成下面这条（只有镜像 tag 和多出来的 --shm-size 256m 不同，其余完全一样）：

docker run -d --name payment-watcher --restart unless-stopped -e TZ=Asia/Shanghai -e WORKER_URL="你的支付站地址" -e TRANSPORT_KEY="你的Watcher传输密钥" -e EDGEPAY_LICENSE="你的License" -e POLL_SECONDS=15 -e MAX_CONCURRENCY=2 -e WATCHER_STORAGE_DIR=/app/var/storage -v "你的存储目录":/app/var/storage --shm-size 256m --security-opt no-new-privileges:true ghcr.io/suk-ldev/edgepay-watcher:latest-browser

跑起来之后看日志确认已连上支付站：

docker logs -f --tail=100 payment-watcher

以后升级镜像（以下为 Linux / NAS 的 sh 或 bash 命令）：先拉取当前容器所用的同源、同标签镜像，成功后再停止并移除容器。

docker pull "$(docker inspect payment-watcher --format '{{.Config.Image}}')" && docker stop payment-watcher && docker rm payment-watcher

随后使用原来的 docker run 命令重建。保持域名、密钥、License、镜像标签与宿主机目录不变；不要删除持久化目录。停机期间监听会短暂中断，请选择合适时段操作。

方式二：compose 文件（长期维护更顺手）

以下命令用于 Linux / NAS 的 sh 或 bash。新建目录并创建 .env，启动前将域名、密钥与 License 替换为真实值：

mkdir -p edgepay-watcher/storage
cd edgepay-watcher
cat > .env <<'EOF'
TZ=Asia/Shanghai
WORKER_URL=https://pay.example.com
TRANSPORT_KEY=部署完成页的-WATCHER_TRANSPORT_SECRET
EDGEPAY_LICENSE=从-license.imsuk.cn-生成的-EPL1-License
POLL_SECONDS=15
MAX_CONCURRENCY=2
WATCHER_STORAGE_DIR=/app/var/storage
EOF
chmod 600 .env

创建 compose.yaml：

services:
  watcher:
    image: ghcr.io/suk-ldev/edgepay-watcher:latest
    container_name: payment-watcher
    restart: unless-stopped
    env_file: .env
    volumes:
      - ./storage:/app/var/storage
    security_opt:
      - no-new-privileges:true

上方为直连版配置。浏览器插件请将 image 标签改为 latest-browser，并在 watcher 下与 image 同级添加 shm_size: 256mb。按实际负载准备内存，不在通用示例中写死内存上限。

在 compose.yaml 所在目录拉取并启动：

docker compose pull
docker compose up -d
docker compose ps
docker compose logs -f --tail=100
Worker Secret WATCHER_TRANSPORT_SECRET 与容器 TRANSPORT_KEY 必须完全一致；Worker 和容器也必须填写同一 License。
05

微信个人收款：两种监听方式二选一

微信个人收款的到账信息有两条来源，同一个收款微信只能选一种——同时启用会重复投递同一笔到账，增加排错难度。

手机通知监听应用宝协议监听
需要什么一部长期开机的安卓手机一台能跑 Docker 的机器
到账来源微信收款到账通知「收款小账本」小程序的收款流水
收款码类型个人码、经营码都行只支持个人收款码
手机要一直开着吗要不用
经营收款码的流水不进「收款小账本」，应用宝这条链路查不到。用经营码请走手机方式。

手机通知监听

先在后台「插件配置」里打开微信个人收款监听，填 SmsForwarder 密钥、上传收款码并保存，再到通道管理建一条通道，记下通道 ID 和这份配置里的 SmsForwarder 密钥。手机端读取微信/支付宝的到账通知并上报，推荐用官方监听端 App：

下载 EdgePay 安卓监听端

当前版本 v1.4.0 · Android 8.0 及以上 · 仅官方签名，覆盖安装需用同一来源的包。从第三方转发工具切过来时先卸载旧包。

  1. 安装后首次打开，按提示到系统设置里给 EdgePay Watcher 勾选通知使用权——这是读取到账通知的前提，不授权收不到任何通知。
  2. 进「配置」页，Worker HTTPS 地址填支付站地址（与 PUBLIC_BASE_URL 完全一致，结尾不带斜杠）。
  3. 在「微信个人收款」里打开启用此平台，通道 ID 填上面那条通道的数字，SmsForwarder 密钥填后台该配置里的同一把。要同时收支付宝，就在「支付宝个人收款」里照样填一遍。
  4. 打开「运行开关 → 启用到账监听」。
  5. 「后台保障」里按机型开启开机自启、打开保持 CPU 唤醒，并把本应用加入电池优化白名单；一加 / OPPO（ColorOS）等国产系统还要在系统设置里关掉对本应用的后台冻结 / 自启限制，否则监听会被系统杀掉。
  6. 到「测试工具」页点测试心跳确认能连通；「运行日志」里正常每 45 秒一条“心跳已发送”，上报或心跳失败时日志会直接写明原因（握手被拒、密钥不符、配置未解出等）。
App 里填的通道 ID 和 SmsForwarder 密钥必须和后台该插件配置完全一致，差一个空格都会被判为身份不符。密钥在支付后台“密钥管理”轮换后，手机端要同步改。

收款监听节点模块（手机已 root 时可选）

手机已 root 时可用。模块是常驻的 root 守护进程，自己读通知并上报，不依赖 App 进程存活。没有 root 就用上面的 App。

下载收款监听节点模块

当前版本 v0.1.0 · Magisk / KernelSU / KernelSU Next / APatch 通用 · 不含 App。

  1. 在 root 管理器里刷入 zip，然后重启手机。
  2. 跑一次自检：KernelSU / APatch 点开模块的 WebUI；Magisk 用终端执行 su -c /data/adb/modules/edgepay_node/edgepay-node selftest。
  3. 填配置：KernelSU / APatch 在 WebUI 里填；Magisk 装上面那个 App，在它的「配置」页填。App 里已有配置时会自动同步给模块。
模块运行时 App 停止自行监听并收起常驻通知，主页显示模块状态；停用或卸载模块后 App 自动接回。模块配置存在 /data/adb/edgepay/，卸载模块时一并删除，需要留底先在 WebUI 导出。

也可以用第三方通知转发工具（如 SmsForwarder）：它们说同一套协议，把通知地址 /api/pay/{通道ID}/notify 和同一把密钥填进去即可，但需自行处理保活与掉线排查。

应用宝协议监听（付费插件 yyb_receipt）

应用宝协议服务已内置进官方 Docker Watcher 镜像（直连版与浏览器版都带），不需要再单独部署容器。买 yyb_receipt 插件、配好通道，已在跑的 Docker Watcher 就会自动接管这条通道。

  1. 在 License 站购买 yyb_receipt（用同一个 License），并按第 04 步正常部署 Docker Watcher；WORKER_URL / TRANSPORT_KEY 都复用 Watcher 自己的，不需要额外的密钥或通道号。
  2. 后台「插件配置」里打开微信个人收款(应用宝协议)，选识别模式（建议金额变动）、上传要收款那个微信的个人收款码并保存；再到通道管理建一条 yyb_receipt 通道。
  3. 看 Docker Watcher 的日志，里面会直接给出微信扫码链接，用要收款的那个微信扫码登录：
================ 请用微信扫码登录 ================
  https://open.weixin.qq.com/connect/qrcode/xxxxxxxx
  用浏览器打开上面的链接，用要收款的那个微信扫码并确认
=================================================

登录态保存在 Watcher 的数据卷内，重启会复用。它每 15 秒检查支付站的待支付订单，有单时才查「收款小账本」流水、按金额匹配后上报——上报走 Watcher 通道通知路径（用传输密钥验签、支付站 D1 去重），不借用微信个人通知通道，也不需要短信密钥。

掉登录会自动暂停通道、重登自动恢复。登录失效或还没扫码时，这条通道会被支付站自动暂停（约 2 分钟）；重新扫码登录后自动恢复，无需人工开关通道。后台「渠道通知」配好推送后，掉线/恢复会主动提醒。

两个微信一起收款

一个微信收商业单、另一个微信收个人单时，在「插件配置」里点微信个人收款监听那行的复制：填写便于区分的名称，勾选“同时新建通道”，就会多出一个副本（编码形如 wxpay_receipt~2）和它自己的一条通道。

  • 两个账号的密钥、收款码、订单、流水去重全部分开；复制时不会带走原账号的密钥和收款码，必须各填各的。
  • 分流看通道权重：两条通道同为 wxpay，权重 70 / 30 就是七三分，把一边调成 0 就等于只走另一个账号。
  • 两个账号各自选监听方式：手机方式（wxpay_receipt）多台手机即可；走应用宝（yyb_receipt）的话一个微信一台 Docker Watcher 容器——不支持在同一容器里登录多个微信，各挂独立的 storage/、各扫各的码。
  • 后台「渠道通知」里配好推送后，监听掉线的告警会直接写明是哪条通道。应用宝通道掉登录时会自动暂停、重新登录后自动恢复，各通道分别告警，不会互相盖掉。

无损升级

  1. 管理后台发现新版本时，点击“前往升级”；也可以直接打开 deploy.imsuk.cn。
  2. 填写原 Cloudflare 账号、原 Worker 项目名、公开访问地址和 License。
  3. 向导发现同名 EdgePay 后会弹窗询问。确认升级后只替换程序文件。
  4. 原 D1、插件配置、支付通道、环境变量、Secrets、定时任务和访问路由都会保留，不需要重新填写后台配置。
  5. EdgeOne Makers 部署的项目：后台“前往升级”会直接进入 Makers 流程；手动打开部署站时选择 EdgeOne Makers，填原项目名。数据库、密钥、定时轮询地址和绑定的域名都保留，表结构在支付站下次连库时自动补齐。
如果同名 Worker 或 Makers 项目不是原 EdgePay，选择返回并重新填写项目名，向导不会覆盖它。
07

更新与排错

先记录页面或日志中的具体错误，再定位对应环节。分享日志前，请移除 Token、License、Cookie、密钥和付款信息。

# 更新镜像
docker compose pull && docker compose up -d

# 查看状态和最近日志
docker compose ps
docker compose logs --tail=200 watcher

# 核对实际镜像摘要
docker inspect payment-watcher --format '{{.Image}}'
  • 出现“License 域名不匹配”：检查 WORKER_URL、Worker 的 PUBLIC_BASE_URL 与 License 域名。
  • 出现传输签名错误：重新核对 TRANSPORT_KEY。
  • 浏览器型插件启动失败：确认使用 latest-browser、配置了共享内存，并根据容器日志检查可用内存。
